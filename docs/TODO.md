# ECDAT — TODO / Issue Backlog

Prioritized list of actual issues found while documenting the codebase on 2026-09-14 (see `CHANGELOG.md`). Nothing here has been implemented yet — this is a backlog for future, explicitly-requested work.

## High Priority

1. **No dependency manifest for the backend.** No `requirements.txt`, `pyproject.toml`, or `Pipfile` is committed; the only record of dependencies is whatever happens to be installed in the local `backend/venv`. A fresh clone cannot be set up without guessing package versions. (`fastapi==0.141.1`, `uvicorn==0.52.4`, `requests==2.34.2` observed in the venv)
2. **Generic exception handling on `/api/ai/advice`.** All failures (Ollama unreachable, network error, malformed data) collapse to a single HTTP 500 with a raw Python exception string — no way for the frontend to distinguish or handle them differently. (`backend/main.py`) — Note: an asset simply not existing in the report is *not* an error case (fixed 2026-09-14, degrades gracefully) — this item is now specifically about infrastructure-level failures (Ollama down, corrupt/missing data file).

## Medium Priority

3. **Fixed CBOM filename regardless of analyzed repository.** `cbomkit_client.py` always writes to `data/keycloak-cbom.json`; results from only one repository can exist at a time, and no output file records which repository/branch/timestamp it came from. (`backend/cbomkit_client.py`, `backend/cbom_parser.py`)
4. **Repository backup/duplicate clutter tracked in git.** `backend/main_backup.py`, `backend/main_backup_before_pipeline.py`, `backend/cbom_parser_backup.py`, the entire `data-backup/` directory (a duplicate of `data/`), and duplicate `demo/cbom.json` / `demo/cbom (3).json` are all committed. These inflate the repo and risk someone editing the wrong (stale) file. `backend/score_contextual_cbom.py` joined this category on 2026-09-14 (deprecated, kept for reference, no longer part of the active pipeline).
5. **AI advisor has no client-side timeout or cancel**, while the backend itself allows up to 300s per Ollama call and caps output at `num_predict: 300` tokens (risking mid-sentence truncation of the SUMMARY section) with no truncation indicator shown to the user. Live tests took 33–49s per answer in this environment. The loading copy now warns generation "can take up to a few minutes," but there's still no cancel button and no way to abandon a request short of navigating away (the backend call keeps running regardless). (`frontend/src/components/AIAdvisorPanel.jsx`, `backend/services/ai_advisor.py`)
6. **AI advisor prompt/response has no streaming**, so the UI shows a loading state with no incremental feedback for up to 5 minutes.
7. **Hardcoded external-service URLs** (`OLLAMA_URL`, `CBOMKIT_URL`, and the frontend's `API_BASE_URL = "http://127.0.0.1:8000"`) — no environment variables or config file, so pointing at a different host/port requires editing source in three separate files. (`backend/services/ai_advisor.py`, `backend/cbomkit_client.py`, `frontend/src/api.js`)
8. **No automated regression tests for `services/ai_advisor.py`, `cbomkit_client.py`, the FastAPI app, or any frontend component** — the extensive `backend/test_*.py` suite covers most `services/` scoring modules (now including per-asset context derivation, see Completed) but not the API layer or the AI integration end-to-end; the frontend has no test framework at all. Several rounds of backend fixes were verified manually/live (see `CHANGELOG.md` for the test logs) rather than by an automated suite that would catch a future regression. (`check_risk_consistency.py`, added 2026-09-14, is a partial mitigation specifically for risk-figure drift — it is not a general test suite.)
10. **No CORS restriction** — the backend sets `allow_origins=["*"]`, `allow_methods=["*"]`, `allow_headers=["*"]`, which is fine for local dev but would need tightening before any non-local deployment. (Not urgent while ECDAT is local-only, but worth flagging before any deployment work.)
11. **`backend/test_api_validation.py` / `backend/test_api_integration.py` are confirmed stale.** Both fail on their first assertion against current data (`total_assets == 59` — actual is 57; `GET /api/asset/ECDH` — no `ECDH` asset exists in the current `data/ecdat-migration-report.json`, which now reflects a different scanned project than whatever these tests were originally written against). Confirmed via `git stash` that both failures reproduce identically on unmodified code, so this is a pre-existing fixture/data drift, not a regression — but it means this suite currently provides no working regression coverage and should be refreshed or parameterized against whatever dataset is actually checked in.
12. **Bundle-size warning: single JS chunk over 500 kB (588.40 kB as of the 2026-09-14 frontend overhaul, up slightly from ~582 kB before it).** `vite build` warns that the main chunk exceeds 500 kB after minification. Pre-existing; grew slightly from the frontend overhaul's added components (presentation-only, no new dependency) but was not the cause of the original warning. Not addressed — would need `React.lazy`/dynamic `import()` code-splitting, out of scope for UI passes explicitly asked not to restructure the app's module-loading strategy.
13. **Unidentifiable process observed holding port 8000, persisting across sessions.** `netstat`/`Get-NetTCPConnection` reports PID 36872 as the `LISTENING` owner of `127.0.0.1:8000`, still correctly answering `/health`, while neither `tasklist` nor `Get-Process`/`Get-CimInstance` can find any process with that PID — confirmed still present across multiple rounds now, using the exact same PID number each time. Not resolved (no broad process-kill attempted, to avoid affecting unrelated processes). Harmless in practice (`main.py` does no in-memory caching, so any process serving that port reflects current disk state), but worth the user checking manually (Task Manager "show processes from all users," or a reboot) if nothing is meant to be persistently running there.
14. **`generate_blast_radius.py` produces non-deterministic array ordering across separate runs.** Discovered 2026-09-14 while diffing pipeline output before/after an unrelated change: re-running the pipeline on identical input reordered (not changed the values of) dependency-ref arrays inside `ecdat-blast-radius.json`, which then rippled into a display-order-only diff in `ecdat-migration-priority.json`. Root cause is very likely Python's per-process string-hash randomization affecting `set`/`dict` iteration order somewhere in `services/dependency_graph.py` or `generate_blast_radius.py`'s own aggregation code. Not fixed; the fix would likely be sorting these lists before serialization.
15. **`test_pqc_mapper.py` crashes with `UnicodeEncodeError`** on a Unicode arrow character in a `print()` statement, the same pattern found and fixed in `generate_migration_actions.py` in an earlier round — but in a different, untouched file. Not fixed; same one-line fix (replace `→` with `->`) would apply.

## Low Priority

16. **No pagination on list endpoints** (`/api/assets`, `/api/risk`, etc.) — every request returns the full dataset; fine at current data sizes (hundreds of assets) but will not scale to very large repositories.
17. **`frontend/src/api.js` duplicate comment block** — a leftover `// AI Migration Advisor` section header is duplicated at the end of the file with nothing under the second copy.
18. **No `.env.example` despite `.gitignore` anticipating `.env`/`.env.*`** — nothing currently reads from environment variables at all, so the gitignore entries are presently unused.
19. **`App.jsx` is still a single large orchestrator component.** Presentational pieces (`Badge`, `StatCard`, `DistributionBar`, `States`, `AIAdvisorPanel`) were extracted into `frontend/src/components/` in an earlier round, but state/effects/layout still live in one file. Further splitting (e.g. an `AssetTable` component, a `Filters` component) would help but wasn't done, per instruction to refactor only where it gives a clear benefit and not rewrite blindly.
20. **No router** — the whole dashboard is one scrollable page with `scrollIntoView` "navigation," which works but means there are no deep-linkable URLs for a given section or asset.
21. **`/api/ai/advisor` (legacy, body `{asset_name}`) is confirmed-dead code**, kept only for backward compatibility since nothing references it. Candidate for removal in a future cleanup round once confirmed truly unused in any external consumer.
22. **Local dev environment cannot currently run `oxlint`** (`npm run lint` fails with an OS Application-Control-policy block on a native binary) — needs a machine-level fix (reinstall/allow the native binding), not a code fix.
23. **`DistributionBar` and `LoadingState` are defined-but-unused utility components** — `DistributionBar` was already unused before the UI round (moved as-is); `LoadingState` was added alongside `ErrorState`/`EmptyState` but no current call site needed a bare loading indicator distinct from what's already inline. Both remain available, matching the pattern already established by the pre-existing unused `DistributionBar`.
24. **`generate_migration_priority.py` labels the full contextual risk score `"quantum_risk"` in its output** (e.g. `/api/priority`'s per-asset `quantum_risk.score` is actually the weighted contextual `final_score`, not the quantum-only `base_risk` score `/api/risk` reports under the same conceptual name). Purely a naming/labeling clarity issue — the *value* is correct and consistent with the authoritative source, only the field name is confusing next to `/api/risk`'s same-named-but-different concept. Not fixed (cosmetic, and changing a field name would be an API response format change).
25. **`services/risk_context.py`'s heuristics are simple and keyword-based, not a claim of perfect accuracy.** E.g. a production file merely named `test_helpers.py` would be caught by the `"test"` low-criticality keyword even if it's shared production tooling; the network-exposure keyword list is a reasonable but non-exhaustive set. Documented and auditable (see `ARCHITECTURE.md` §11), but a future round could refine the heuristics (e.g. distinguishing a leading `test/` directory from a filename merely containing "test") if real-world false positives/negatives are observed.
26. **`data_lifetime_years` and `quantum_threat_horizon_years` remain fixed, global constants** (not derived per asset or per project — see `ARCHITECTURE.md` §11 for why). A future round could make these configurable per analysis (e.g. an optional field on `POST /api/analyze` or a project-level settings file) without touching the per-asset derivation logic added 2026-09-14; explicitly out of scope for that round since it excluded frontend changes.
